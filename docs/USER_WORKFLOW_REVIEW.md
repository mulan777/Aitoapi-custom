# 使用者工作流审查（2026-09-06）

## 本轮确认的问题

1. **凭证缺少生命周期管理**：此前只有“过期”标记，没有独立的手动禁用、自动禁用原因和恢复入口。
2. **403 会继续参与轮询**：无权限凭证没有立即退出轮询池，可能重复失败并触发无意义的上下文重建。
3. **重试参数不可在线维护**：`MAX_RETRIES`、`RETRY_DELAY` 只能依赖启动环境，控制台修改后也无法持久化。
4. **模型冷却信息不透明**：界面只显示“模型冷却”，没有显示模型名和剩余时间；进程重启后内存状态丢失。
5. **统计与凭证脱节**：全局统计已有记录，但凭证列表看不到“今天、这个账号、这个模型”的成功/失败数量。
6. **429/用量轮换存在竞态**：备用账号预热会逐个执行全局预清理；并发请求会互相中止初始化，并可能先关闭旧槽位再发现新槽位不可用。
7. **模型发现缺项**：可直接调用的 `gemini-3.8-flash` 未进入 `models.json`，因此 `/v1/models` 不展示。

## 修正后的使用者行为

- 凭证卡片可暂停/启用；禁用凭证仍保留文件和统计，但不参与请求路由。
- 默认遇到 401/403 自动禁用，状态码列表可在设置中维护并持久化。
- 429 只影响发生限流的原始模型，冷却模型、截止时间和命中次数持久化到 `data/account-route-state.json`。
- 每张凭证卡片直接展示今日总成功/失败和每个模型的成功/失败。
- `MAX_CONTEXTS=5` 时维持五个热槽位；轮换采用“目标 ready → 旧槽位关闭/延迟关闭”，不会为了探测候选反复清空池。
- 最大重试次数与重试间隔可在线修改，写入 `configs/runtime-settings.json`。

## 后续建议

- 增加批量启用/禁用和按禁用原因筛选。
- 给每日统计增加时区选择；当前按服务器本地日期统计。
- 将“测试凭证”扩展为可选模型探测；默认测试仍只验证浏览器和 WebSocket，避免消耗模型额度。
- 生产监控增加：主浏览器启动次数、上下文替换成功率、429 模型冷却数量、自动禁用数量。
