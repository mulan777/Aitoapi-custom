## 二开内容

- 扩展模型列表配置，支持更多模型元数据与模型别名。
- 支持模型名后缀组合，用于思考等级、流式模式、联网搜索和代码执行等能力选择。
- 恢复模型发现接口中的后缀变体，例如 `gemini-3-flash-preview-high-fake-search`；这些变体与直接请求时的后缀解析保持一致。
- 增强模型发现与请求转换逻辑。
- 增加思考等级与 `includeThoughts` / 输出配置的兼容处理。
- 修复多账号并发请求的全局账号漂移：请求会绑定到一个活跃账号连接并轮询分配，重试也保持请求级路由；保活器现在按账号上下文独立运行。将 `MAX_CONTEXTS` 设置为 `2` 或更多即可同时保持多个账号在线。
- `BackgroundWakeup / Rocket Handler` 也已改为按账号独立运行；切换当前账号、单账号重连或关闭某个账号时，不会停止其他账号的保活。
- 保留上游的 OpenAI、Gemini、Anthropic 兼容接口和 Web 控制台。

## 多账号轮询

当前实现支持类似“5 个账号同时在线、请求轮询分配”的模式：

1. 将 5 份登录后的认证文件放入 `configs/auth/`。
2. 在项目根目录的 `.env` 中设置：

   ```dotenv
   MAX_CONTEXTS=5
   ```

3. 启动服务：

   ```powershell
   npm run build:ui
   npm start
   ```

启动时第一个账号先就绪，其余账号在后台依次加载；加载完成后，只有已建立 WebSocket 的账号会进入轮询池。每个请求只分配给一个账号，流式响应和重试继续绑定原请求账号，不会把同一请求复制发送给 5 个账号。

`MAX_CONTEXTS` 默认仍为 `1`，设置为 `5` 才会同时维持最多 5 个账号上下文。每个账号都需要独立浏览器上下文和 WebSocket，因此内存占用会明显增加。

### 429 和请求调度

- 普通轮询只在“同一优先级下”使用轮询；有长流式请求时优先选择当前在途请求更少的账号，避免把请求继续堆到一个账号上。
- 某个账号返回 HTTP 429 后，该账号立即进入独立冷却，不再接收新请求；当前请求可以在剩余健康账号中进行有限重试。
- 冷却时间默认 5 分钟，连续再次触发会指数延长，最长 30 分钟，可用 `ACCOUNT_COOLDOWN_MS` 和 `ACCOUNT_COOLDOWN_MAX_MS` 调整。
- 账号列表中的“测试”按钮只检查该账号的 Auth、浏览器上下文和 WebSocket，不发送模型生成内容；同时会刷新该账号的冷却状态。

## 关于 build 和保活

`npm run build:ui` 只负责构建前端静态资源，不是保活进程。真正保持浏览器上下文、WebSocket 和账号保活的是持续运行的 `npm start` 进程；关闭终端或结束 Node 进程后，5 个浏览器上下文都会停止。Windows 部署建议把 `npm start` 注册为任务计划程序或服务；Docker 部署使用 `--restart unless-stopped`，即可在容器异常退出后自动拉起。
